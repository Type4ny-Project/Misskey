外部AIリアクション候補の導入

管理画面の外部サービス設定から、対応するWorkersと接続します。
Workersは別途デプロイが必要です。

設定

  1. 外部サービスにHTTPSの /v1/suggest URLを設定する。
  2. Workersの API_TOKEN と同じキーをAPIキー欄へ設定する。
  3. タイムアウトを120000ms、候補数を5に設定して有効化する。
  4. 対象インスタンスの絵文字をWorkersへ初回インポートする。

参考実装は mk-emoji-suggest です。
PoCには画像配信元の制限があるため、自サーバーの配信元を確認して構成してください。

処理順序

ピッカー → 認証済みの notes/reactions/suggestions → 投稿の閲覧権限確認 → Redisキャッシュ → Workers → 現在の絵文字・ロール制限確認 → ピッカー。

キャッシュは1時間です。
同一プロセス内の同時リクエストも共有します。
本文・公開範囲・添付情報・接続設定が変わると別のキャッシュキーになります。
取得のたびに閲覧権限を確認します。

送信するデータ

公開・ホーム投稿の正規化本文と、対応形式の最初の非センシティブ画像を送信します。
CWがある場合はCWとタグだけを使用し、本文と画像は送りません。
限定公開投稿は推論対象にしません。
APIキーはバックエンドに保持します。

Workerの契約

emoji-suggest-worker-request-v1 を送信し、emoji-suggest-worker-response-v1 の候補・理由・モデル版・索引版を受け取ります。
絵文字通知は /v1/emojis へ emoji-suggest-sync-v1 のupsert/deleteを送ります。
両ルートはBearer認証が必要です。

運用上の制限

初回のAI推論には数秒以上かかります。
複数プロセス間の同時初回推論は統合していません。
絵文字通知失敗時の永続的な再送と、一括カテゴリ・別名編集の通知は未対応です。
失敗時はログを確認し、再更新またはカタログ再インポートを行ってください。
