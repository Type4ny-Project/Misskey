# T03 お知らせへのリアクション

元提案は[新島さんの投稿](https://freeski.msnis.net/notes/arx2uvf9rtfz01ne)。既存のお知らせはノートとは別のモデルで、取得したモデル・画面にリアクション欄はなかった。

ユーザーが以下の仕様を採用し、管理者集計とリアクション時の既読を追加指定した。

## 採用した仕様

お知らせの詳細画面にリアクション欄を追加し、一覧にも集計を表示する。ログイン済みの閲覧対象者は1人1種類を付けられ、変更・取り消しができる。最初はノートと同じ絵文字選択UIを使い、絵文字の利用権限を守る。

管理者はお知らせ単位でリアクションを有効化できる。既存のお知らせと新規作成時の既定値は無効とする。リアクションの追加・変更が成功すると既読にする。未読かつ確認必須のお知らせでは、リアクション前に既読になる旨を確認する。確認取消・API拒否では未読のまま、リアクション取消では現在の既読状態を維持する。「わかった」ボタンの既存確認も維持する。個人向けのお知らせは対象者以外に通常APIで集計や操作権限を公開しない。管理者・モデレーターは管理APIから全体向け・個人向けの集計を確認でき、無効化後も保存済み集計を表示する。

初期版は集計と自分のリアクションを表示する。反応者一覧、リアクション通知、連合は追加しない。お知らせの本文更新ではリアクションを維持し、削除時は関連するリアクションも削除する。

## 既存コードと実装の入口

`packages/backend/src/models/Announcement.ts`、`packages/backend/src/core/entities/AnnouncementEntityService.ts`、`packages/frontend/src/pages/announcement.vue`、`announcements.vue`、管理画面のお知らせ編集を入口とする。ノートの`ReactionService`をそのまま呼ぶのではなく、お知らせIDに紐づく記録を持たせる。API型再生成と新規migrationが必要になる見込み。

## 完了条件

- [x] 有効なお知らせに追加・変更・取消ができ、集計と自分の状態が再読込後も一致する。
- [x] 無効のお知らせと閲覧対象外のお知らせにAPIからも反応できない。
- [x] リアクションの成功時に既読になり、必要な場合は事前確認する。確認取消・API拒否で未読を維持する。
- [x] 全体向け・個人向けの管理編集画面に絵文字と件数を表示する。

## 未決事項

初期版は採用された1人1種類で実装した。ポップアップには、既読にせず詳細画面を開くリンクを設ける。リアクション操作は詳細画面で行い、一覧は集計と自分の反応を表示する。

## 検証結果

2026年10月4日に専用worktree・専用PostgreSQL/Redisで確認した。API E2Eは11件、既存AnnouncementServiceのunit testは5件、リアクションUIのunit testは8件が通過。backend・frontendの型チェック、frontendビルド、API型再生成、変更ファイルlint、locale safetyも通過した。

ブラウザーでは管理画面の有効化・無効化、詳細画面での追加・ピッカーによる変更・取消、再読込後の状態、「わかった」の確認取消と確定を確認した。一覧は再読込後に集計と自分の状態を確認し、390px幅で横スクロールが生じないことも確認した。PRレビュー後には、ピッカーの合字絵文字と保存されたUnicode絵文字の値でも別ユーザーが同じ反応を追加できることをAPI E2Eで追加確認した。利用ロールは全ロールを取得できるAPIで検証する。ピッカーでは権限のない候補も選択できるが、APIが拒否し、表示状態を維持する。公開ロールだけを参照する画面側の制限は、非公開ロールで許可された絵文字まで拒否してしまうため採用しない。[詳細画面](screenshots/detail.png)と[一覧](screenshots/list.png)のスクリーンショットを保存した。

最新の`origin/develop`（`fcd64ff1766e`）をマージした後、既存migration履歴を空の専用DBへ全適用し、`check-migrations`がpending DDL 0件で通過した。以前に記録したスキーマ差分とSPDX欠落はdevelopに入った修正で解消し、変更ファイルlint・SPDX・locale safetyも通過した。API生成ファイルは統合後の生成器で再生成した。Storybook全体のビルド・表示は未検証。

残る制限として、リアクション文字列のAPI・保存上限は128文字のため、127〜128文字の名前を持つカスタム絵文字は利用できない。

追加依頼の動作確認では、リアクションの事前確認を取り消して未読・反応なしを維持し、承認後に既読となり「わかった」ボタンが消えることと、未読一覧から除外されることをブラウザーとAPIで確認した。個人向けはリアクション成功後にアーカイブされ、管理者がアーカイブ側から集計を確認できる。390px幅で横スクロールもない。

管理者向けには集計の見える[全体のお知らせ編集](screenshots/admin-global.png)と[特定ユーザー向けのお知らせ編集](screenshots/admin-personal.png)を撮影した。「リアクションを有効にする」の下に絵文字と件数を表示する。[既読の事前確認](screenshots/reaction-confirm.png)も保存した。反応者一覧は追加していない。
