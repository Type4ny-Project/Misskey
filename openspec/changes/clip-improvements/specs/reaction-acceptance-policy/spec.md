# T09 ロールによるリアクション受け入れ制限の可否

元提案は[Yusukeさんの投稿](https://freeski.msnis.net/notes/arx2yzusrtfz022b)。一部の人がリアクションの受け入れを制限できないようにする提案で、具体的な対象者を挙げた冗談を含む。対象者名をコードへ埋め込む仕様にはしない。

ユーザーがロールで制限できる方式を採用した。受け入れ制限を設定できるかを既存ロールポリシーで制御する。T02の1人あたりの個数上限とは分けて扱う。

## 採用仕様

既存のロールポリシーとして「リアクション受け入れ設定を変更できるか」を追加する。既定は変更可能。変更不可のロールを管理者が設定した場合、対象ユーザーの新規投稿はセンシティブな絵文字を含むすべてのリアクションを受け入れる（`reactionAcceptance: null`）。設定画面と投稿フォームには、ロールにより変更できない理由と固定状態を表示する。2026年10月4日のユーザー回答でこの挙動を確定した。

受け入れ設定だけを扱い、ブロック、公開範囲、絵文字を使えるロール権限は維持する。一般ユーザーが他人の受け入れ設定を上書きする操作は設けない。既存ノートを一括で書き換えず、初期案では新規投稿にだけ適用する。APIから直接設定を送っても同じロール方針を適用する。

## 既存コードと実装の入口

`packages/frontend/src/pages/settings/profile.vue`に受け入れ設定があり、`packages/backend/src/models/Note.ts`に`reactionAcceptance`、`packages/backend/src/core/RoleService.ts`にロールポリシーがある。`NoteCreateService`でローカルユーザーの新規投稿を固定する。予約投稿にも投稿実行時のポリシーを適用する。`ReactionService`では既存ノートの設定を変更しない。既存ノートの編集画面では保存済みの受け入れ設定を表示し、変更操作を無効にする。クライアント設定と下書きに保存済みの受け入れ設定は維持し、ロール解除後はその設定を再び選択・適用できる。

## 完了条件

- [x] 通常ロールのユーザーは従来どおり受け入れ設定を選べる。
- [x] 固定ロールのユーザーには固定状態と理由が表示され、UI・APIから新規投稿の設定を回避できない。
- [x] 過去のノート、ブロック、公開範囲、絵文字の利用権限の挙動を変えない。

## ロールの競合

既存のbooleanポリシーと同じ優先度計算を使う。同じ優先度では変更許可を優先するため、変更を禁止するロールは許可ロールより高い優先度に設定する。絵文字の利用権限やブロックを解除する機能ではない。
