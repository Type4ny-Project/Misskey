# T01 タイムラインの1行表示

元提案は[端島さんの投稿](https://freeski.msnis.net/notes/arx2y1gxrtfz0205)。添付動画では、投稿者・時刻・本文を細い行に並べた一覧を確認できた。目的は、多数のノートを少ないスクロールで遡れること。

ユーザーは1行表示のタスク化を了承し、CWの扱いを詰める必要があると指摘した。以下のCW表示は具体化した案で、既存の開示操作を維持する。

## 仕様

タイムラインに「通常／1行」の表示切り替えを追加する。既定は通常。選択は既存のクライアント設定の仕組みで保存する。1行表示では小さなアイコン、投稿者、時刻、本文要約を並べ、改行は空白へ置換し、幅を超えた本文は省略する。狭い画面でも横スクロールを要求しない。

行から既存のノート詳細へ移動できる。添付メディア・投票・リアクション一覧・URLプレビューは一覧内で展開せず、存在を短い印で示す。CWがあるノートはCWだけを要約し、本文を露出させない。返信・Renoteは区別できる印を付け、既存のミュート・ブロック・公開範囲の扱いを維持する。

CWの警告文がある場合は、CWの印と警告文の要約を表示する。空のCWは「内容を隠したノート」と表示し、通常の空本文と区別する。行を選んだだけで本文や添付を開示せず、詳細側の既存の「内容を表示」操作で開く。初期版の1行表示には独自のインライン開示状態を追加しない。行のラベルやツールチップにも隠した本文を流用しない。

対象はまず通常のタイムライン表示とする。Deckや検索結果への追加は今回の初期範囲に含めない。取得APIやページングは既存のものを使い、ノートごとに詳細APIを呼ぶ構成を作らない。

## 既存コードと実装の入口

`packages/frontend/src/components/MkNotesTimeline.vue`、`MkStreamingNotesTimeline.vue`、`MkNote.vue`、`packages/frontend/src/utility/get-note-summary.ts`、`packages/frontend/src/preferences.ts`を確認する。既存の`MkNoteSimple.vue`は1行表示ではないため、そのまま完成扱いにしない。

## 完了条件

- [x] 通常表示と1行表示を切り替えられ、再読込後も選択が残る。
- [x] 長文、CW、添付付き、返信・Renoteを代表例で確認し、詳細を開ける。
- [x] 警告文あり・空CWの両方を識別でき、本文・添付は既存の開示操作まで表示しない。
- [x] 遡りの追加読込、削除・編集の反映、ミュートが機能し、切り替え時に閲覧位置を大きく失わない。

## 適用範囲

通常タイムラインページ（ホーム・ローカル・ソーシャル・グローバル・メディア、および同ページで選択するリスト・アンテナ・チャンネル・ハッシュタグ）に適用する。独立した各一覧ページ・Deck・検索結果・ウィジェットは既定の通常表示を維持する。動画中のアプリ固有機能を丸ごと移植する要求とは解釈していない。

## 検証

ローカル Vite と合成データで実際のタイムライン・ノート詳細コンポーネントを操作して確認した。メニューから切り替え、再読込後の選択保持、警告文あり・空 CW の詳細移動と既存ボタンによる開示、追加読込（15→45件）、編集・削除イベント、ソフト／完全ミュート、通常表示から切り替えた後の Enter 操作を確認。375px 幅では行の高さ32px、横方向のはみ出しなし。切り替えで API 再取得は発生せず、表示中のノートの位置変化は約9pxだった。

[デスクトップ画面](../../../docs/screenshots/compact-timeline-desktop.png)と[モバイル画面](../../../docs/screenshots/compact-timeline-mobile.png)は合成データで撮影した。本番接続と backend の権限処理を含む E2E は今回の検証に含めていない。

PR レビューで、長いノートの途中から縮小すると同じノートが画面上へ消えるケースを再現して修正した。Playwright で250pxのノートを9px／150px読み進めて32pxへ縮小する場合と、32pxから250pxへ戻す場合を確認し、いずれも同じノートが表示範囲に残った。
